# 联合执法保密分舱

保存联合执法中“按阶段分舱”的角色、批次、人员、材料、解封条件与结案追溯约定。仓库只保存约定与**完全虚构**的样例，并负责读取与校验；它不是访问控制系统，业务服务可沿用相同标识、动作名和版本约定自行实现授权执行。

## 领域资料

| 文件 | 作用 |
| --- | --- |
| `contracts/context.schema.json` | 基础事实资料的格式 |
| `fixtures/context.json` | 领域事实清单（v2） |
| `contracts/case.schema.json` | 分舱专案约定文档的结构（形状约束） |
| `fixtures/case.json` | 端到端虚构专案样例，由脚本生成 |
| `src/context.js` | 读取基础事实资料 |
| `src/case.js` | 读取并校验专案文档的跨记录不变量 |
| `scripts/build-fixture.mjs` | 重新生成样例（自动封缄事件链与回执摘要） |

所有样例中的人员、单位、地点、账号均为虚构，不含真实个人信息。

## 模型要点

- **舱位（compartment）** 与 **行动批次（batch）**：如日常检查舱、核心侦查舱、资金分析舱、起诉移送舱；舱位按解封条件开启——定时、批次激活、或两名指定负责人人工批准。
- **核心名单（core_entries）**：嫌疑人、仓库、资金账户三类条目。初始名单之外，只有两名**不同单位**负责人共同批准的 `core-list-expanded` 事件才能扩围。
- **授权（grant）**：常驻或临时（`temp`），动作包括查看、摘录、转交、授予临时权限；临时授权有生效/到期窗口与授予事件依据，另有到期、撤销与人员调离三种失效方式。核心材料要求 `core_clearance`。
- **只追加日志（events）**：每条事件带自摘要与 `prev_hash`，形成哈希链；查看、摘录、转交、临时授权、止损封舱、批次延期/激活、线索关联、名单扩围全部入链，历史合法操作不因后续状态变化而删除。
- **线索关联（leads）**：普通线索声明关联条件（如收网批次激活），条件达成前的 `lead-linked` 事件视为违规。
- **紧急止损（emergency-freeze）**：封舱即时阻止访问，解除后恢复；期间任何访问都校验失败。
- **跨部门回执（receipts）**：每次跨单位转交必须有接收方确认、接收时间与材料清单摘要。
- **来源链（materials.derived_from / provenance_summary）**：公开检查材料可经 `intake/extract` 进入专案证据，起诉副本必须能回溯到专案证据；公开材料不得反向引用专案或起诉材料。
- **结案获知报告（closure.knowledge_report）**：从日志重建“谁在何时、依据哪条事件、获知哪些材料”，与报告双向核对。

## 本地校验

```bash
npm test                 # 校验样例可读取、哈希链完整、领域不变量成立
node scripts/build-fixture.mjs   # 重新生成 fixtures/case.json
```

测试同时包含正例与一组篡改反例：提前解封、越权扩围、条件未达成即关联线索、延期后提前收网、调离后操作、授权到期/撤销后访问、止损期间访问、缺失回执、获知报告漏报等。
